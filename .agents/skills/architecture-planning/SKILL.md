# Architecture & Task Planning

## Purpose

Keep implementation aligned with architecture.md.

## Workflow

Before coding:

1. Read architecture.md.
2. Identify current phase.
3. Inspect existing files.
4. Identify dependencies.
5. Define the smallest implementation required.

## Rules

- architecture.md is the source of truth.
- Do not redesign unnecessarily.
- Do not implement future phases.
- Do not introduce unapproved technologies.
- Prefer simple solutions.

## Task Format

Every task should define:

CONTEXT

TASK

FILES TO MODIFY

CONSTRAINTS

ACCEPTANCE CRITERIA

TEST REQUIREMENTS

## Completion

Verify acceptance criteria and tests before stopping.
